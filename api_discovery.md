# Paris Libraries (Bibliothèques de la Ville de Paris) - API Discovery

This document details the reverse-engineered REST/WCF endpoints used by the Paris public library portal ([bibliotheques.paris.fr](https://bibliotheques.paris.fr)), which is powered by **Archimed Syracuse**.

---

## 1. Architectural Overview

- **Portal Base URL**: `https://bibliotheques.paris.fr`
- **Logon Service Base URL**: `https://bibliotheques.paris.fr/Portal/Recherche/logon.svc/`
- **Account Service Base URL**: `https://bibliotheques.paris.fr/Portal/Services/UserAccountService.svc/`
- **Protocol / Style**: REST over HTTP (WCF JSON services).
- **Authentication Mechanism**: Session-based cookie authentication using `_syrSessGuid` (Syracuse Session GUID) obtained via the logon endpoint, transmitted automatically on subsequent service calls.

---

## 2. Common Request Parameters & Headers

All requests to `UserAccountService.svc` adhere to common parameter conventions:

| Parameter | Type | Required | Description | Example |
| :--- | :--- | :--- | :--- | :--- |
| `serviceCode` | String | Yes | Identifies the Syracuse backend service. Always set to `SYRACUSE`. | `SYRACUSE` |
| `userUniqueIdentifier` | String (GUID) | Optional | Empty string `""` for the currently authenticated primary user. Set to a paired user's GUID to query that linked family account. | `""` or `44d95800c23248efa0334d2c4dc65ce6` |
| `token` | Integer / String | Optional | Client session timestamp / token generated by the web UI (Unix epoch ms). | `1790018455124` |
| `timestamp` | Integer / String | Optional | Cache-busting timestamp (Unix epoch ms). | `1790018455127` |

### Required Headers
- `Accept: application/json, text/javascript, */*; q=0.01`
- `X-Requested-With: XMLHttpRequest`
- `User-Agent: ...`
- Standard cookie jar containing authentication cookies.

---

## 3. Data Format Conventions

### Response Envelope
All Syracuse JSON responses wrap their payload inside a standard ASP.NET / WCF envelope:

```json
{
  "errors": [],
  "message": null,
  "success": true,
  "d": { ... }
}
```

- `success`: Boolean indicating if the call succeeded.
- `errors`: Array of error objects or strings if any error occurred.
- `message`: Optional message or null.
- `d`: The actual response data payload.

### Microsoft JSON Date Format
All dates returned by the Syracuse API follow the Microsoft JSON Date format:
```text
\/Date(epoch_in_ms[+|-]tz_offset_in_hhmm)\/
```

**Examples:**
- `\/Date(1803682800000+0100)\/`: Timestamp `1803682800000` ms UTC with a `+01:00` offset.
- `\/Date(1790373600000+0200)\/`: Timestamp `1790373600000` ms UTC with a `+02:00` offset.

**Parsing logic (Python):**
Extract the integer millisecond value (and optional offset), divide by `1000`, and convert to `datetime.datetime.fromtimestamp(epoch, tz=timezone(offset))` or `datetime.date`.

## 4. Documented Endpoints

### 4.1. Authentication / Logon

Authenticates the user using their library card barcode and password/PIN, setting the session cookie required for subsequent API requests.

- **Endpoint**: `POST /Portal/Recherche/logon.svc/logon`
- **Headers**:
  - `Content-Type: application/x-www-form-urlencoded; charset=UTF-8`
  - `X-Requested-With: XMLHttpRequest`
- **Request Body** (Form-encoded):
  - `username`: Library card barcode (e.g. `22272392XXXXXX`)
  - `password`: Patron account password or PIN (e.g. date of birth in `DDMMYYYY` format)
  - `rememberMe`: Boolean (`true` or `false`)

#### Sample Request
```http
POST /Portal/Recherche/logon.svc/logon HTTP/1.1
Host: bibliotheques.paris.fr
Content-Type: application/x-www-form-urlencoded; charset=UTF-8
X-Requested-With: XMLHttpRequest

username=22272392XXXXXX&password=********&rememberMe=false
```

#### Response & Session Cookie
- **Set-Cookie**:
  - `_syrSessGuid=<session_guid>`: The Syracuse session GUID cookie.
- **Body on Success**:
  ```json
  {
    "errors": [],
    "message": null,
    "success": true,
    "d": "22272392XXXXXX"
  }
  ```
  *(Note: `d` is a string containing the user identifier / barcode / display name, not a dictionary)*
- **Body on Failure**:
  ```json
  {
    "errors": [
      {
        "id": "FormAuthenticationProvider",
        "msg": "Les informations d'identification fournies ne sont pas valides, vérifiez la syntaxe et réessayez.",
        "type": "InvalidCredentials"
      }
    ],
    "message": None,
    "success": false,
    "d": "Anonymous"
  }
  ```
- **Behavior**:
  - Once authenticated, the `_syrSessGuid` cookie is stored in the HTTP client's cookie jar and automatically sent with all subsequent requests to `UserAccountService.svc`.

### 4.6. Renew Loans (Batch Renewal)

Submits one or more active loans for renewal. Syracuse supports batch renewal across multiple holdings in a single request.

- **Endpoint**: `POST /Portal/Services/UserAccountService.svc/RenewLoans`
- **Headers**:
  - `Content-Type: application/json; charset=UTF-8`
  - `X-Requested-With: XMLHttpRequest`
- **Request Body** (JSON):
  - `loans`: Array of loan objects (must include at least `HoldingId`, `Id`, `RecordId`, `RecordBase`, `Title`, `WhenBack`).
  - `userUniqueIdentifier`: Target account GUID (empty string for primary account, or paired account GUID).

#### Sample Request
```http
POST /Portal/Services/UserAccountService.svc/RenewLoans HTTP/1.1
Host: bibliotheques.paris.fr
Content-Type: application/json; charset=UTF-8
X-Requested-With: XMLHttpRequest
```
